# 交接说明

观众网页只有一条问答链路：输入的文字，或百度识别完成后的文字，进入 `POST /api/ask`。程序先弄清这一句问的是什么，再按所问去本机知识库找材料，交给 DeepSeek 官方接口写成回答，发出之前逐句检查。检查后的同一段正文显示在页面上，并送去阿里云朗读。观众看不到检索片段、条目编号和处理经过。

文字问答固定为本地知识库加 DeepSeek。百度语音识别和阿里云语音合成继续使用。

## 项目怎样跑起来

浏览器打开本机网页。网页由 Python 的 FastAPI 提供。知识内容来自已导入的本地资料；提问后按需要请求 DeepSeek。语音识别和语音合成的密钥留在服务器，不进入网页。

```text
web/                 观众看到的页面
app/main.py          网站入口和接口
app/knowledge/readers.py   读取 Excel、Word
app/knowledge/records.py   整理成带归属和限制的记录
app/knowledge/index.py     检索
app/knowledge/understand.py  弄清这一句问的是什么
app/knowledge/materials.py   按所问取材料，标明归属和限制
app/knowledge/compose.py     请模型写、重写和复查
app/knowledge/guard.py       固定回应和逐句检查
app/knowledge/respond.py     一次提问的处理顺序
data/sources/        原始表格、Word 和登记（catalog.json）
data/knowledge-pack/ 由原始资料生成的知识包正文（jsonl），加载后即可检索
data/voices/         复刻音色参考音频与 voice_id 记录
data/persona/        人物规则和风格样本
data/maodun.db       运行后自动生成：知识索引缓存与本机聊天记录（不必随仓库分发）
.env                 馆方自己的密钥（不要提交）
```

密钥、模型地址和“怎样调用接口”不是同一件事。`.env` 只保存账号和开关。真正组请求、填写模型名并发送的程序是 `app/llm/providers.py`。

人物规则、风格和事实也分开进入同一次模型请求：第一条系统说明是 `system_rules.txt`，第二条是按问题选出的风格说明，用户消息里才放这次检索到的材料。风格样本明确标成“不是事实”。没有材料的阅读交流不会把知识库片段塞进请求。

## 一次提问怎样处理

顺序写在 `app/knowledge/respond.py` 的 `_Turn.run` 里。

0. 载入本场全部已完成轮次。程序按预算组织近期原文（默认 6 轮）、较早内容的分段摘要（满 8 轮后）、以及与本问相关的较早原文找回；摘要存在 `focus_json.memory`，原始 turns 仍是权威记录。DeepSeek 的聊天接口无状态，多轮内容由应用随请求提供。
1. 问候、道谢、只有一句“后来呢”、只说“详细一点”、带条码的馆藏固定问法，由程序直接处理，不调用模型。
2. 其余的问题先调用一次模型，读出这一句问的是什么（`understand.py`）。理解请求带上近期原文、摘要和本轮找回的内容。这一步只定去向，不产生回答。读出的结果由程序再核一遍，例如点了名的当今政治人物一定按当代政治处理；解释先前判断时，那句判断可以在更早一轮。
3. 按去向处理：
   - 当代政治、要求改规则：固定的一句，不再调用模型。连续追问时换一句说法。下一句问别的，照常回答。
   - 要我确认或解释没有本人文字依据的私人感情：不查材料。请模型按风格样本写三句候选，程序逐句检查，再请模型判断有没有暗示确有其事或没有其事，取第一句合格的。都不合格才用备用句。
   - 说的是上一句（追问、纠正、问为什么提到某部作品）：把上一句实际说了什么交给模型，让它就着那一句回答。
   - 读书和写作上的建议、日常寒暄：不查材料，直接请模型回答。
   - 问眼下的情况（天气、开放时间）：固定的一句。问是不是真人：固定的身份说明。
   - 其余都要查材料（`materials.py`）。检索后由程序做简短回答安排（动作、要点、是否允许重讲），再把材料与会话视图交给模型。材料附着归属和限制；模型按固定格式交回“用到哪几条、缺什么、正文”。问历史人物时，程序先看这一问是身份、印象、认识经过还是某件往事，再决定留下哪些材料、从哪里说起、日期说到多细。政治运动里的争议不放进这一问的生成；对方若专门追问，就说这一层不在这里展开，不说成历史上没有。原始资料不删。
   - 同一场对话里，生成请求带近期原文、较早摘要和本轮找回的原文，用来认人、认事和去重，不把已经讲过的故事再当新材料。换一种问法、要别的事、追问细节、解释判断、提出另一种说法，走法不同。没有新的合格材料就收住，不编一段新的。新的一场对话没有上一轮，不会说“刚才”。
4. 正文发出前逐句检查（`guard.py` 的 `inspect_output`）。有问题就带着具体问题重写一次。有风险的回答（扣下过材料、带预设、接着上一句、介绍人物、问两者关系）再请模型复查一次。解释判断时不去重截成“刚才说的就是这些”。
5. 重写后仍不合格：没有风险的回答和有身份材料的人物介绍只留合格的整句；其余有风险的改用按原因给出的一句。原因分为技术故障、资料没导入、说不上来、不下断语、当代政治几类，句子不同。本轮结束后更新摘要与开放话题；删除会话时一并清掉派生记忆。

“后来呢”这类接着往下问的话，先找时间不早于上一轮所用材料的记录，按先后交给模型（`materials.py` 的 `later_records`）。

一轮最多五次模型调用。平常的问题仍是两次（理解、回答），有风险的三次，重写再加一到两次；会话摘要由程序增量整理，默认不另调模型。网站启动时加载索引约 20 秒。

每一轮的处理经过存在 `answer_trace` 表里。查看：

```bash
.venv/bin/python scripts/使用.py 诊断                 最近三轮的摘要
.venv/bin/python scripts/使用.py 诊断 --last 10        最近十轮
.venv/bin/python scripts/使用.py 诊断 会话编号 --full   某一场对话的完整记录
```

摘要里的“正文来历”说明这句话是固定句、模型一稿、重写稿、只留下的合格句、备用句，还是请求失败。“提前返回的位置”说明是哪一段程序没有调用模型就给出了回答。这些内容不会出现在 `/api/ask` 的返回里。

改完问答程序后，用问题清单真实跑一遍，再人工对照材料看回答：

```bash
.venv/bin/python scripts/对话检查.py --file docs/验收问题.txt --save 结果.json
```

自动检查只能说明程序没有改坏，不能说明回答的质量。

`.env.example` 是一份没有真实密钥的模板，给新环境抄配置名。程序只读项目根目录的 `.env`；系统里已经存在的同名变量优先，不会被 `.env` 覆盖。

README 只是给人看的运行说明。程序不会执行 README。人物规则在 `data/persona/system_rules.txt`。

网页文件负责观众看到和点到的部分。Python 负责检索、规则、模型和两家语音服务。本项目没有把页面逻辑写进 Python 模板。

## 启动、停止和备份

启动：

```bash
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

停止：在运行这条命令的终端按 Ctrl+C。不要按端口去结束不认识的其他程序。

仓库里应包含程序、`data/persona/`、`data/sources/`（含原始表格）、`data/knowledge-pack/`（知识包正文）以及 `md.wma`、`data/voices/`。`.env` 只留在本机，用 `.env.example` 说明要填哪些项。不要把 `data/maodun.db` 当成知识包上传：它是运行后的会话库和索引缓存，里面可能有本机访客聊天；别人克隆后执行“加载”或“生成”即可重建可用索引。

备份时复制 `.env`、`data/maodun.db`、`data/sources/`、`data/knowledge-pack/` 和 `data/persona/`。恢复时放回这些相对位置，重新安装依赖，再启动。不要把某台电脑的绝对路径写成部署条件。

换电脑、加书和改馆藏都用 `scripts/使用.py`，不需要改人物规则或页面。

- 换一台电脑：安装依赖，放入 `data/sources/` 或 `data/knowledge-pack/`，由馆方填写 `.env`。有知识包就“加载”，只有表格就“生成”，然后“启动”。
- 增加一本书：把章节表和主题表放进 `data/sources/files/`，在 `catalog.json` 增加一个新的 `source_key`，运行“增加”和这个标识。相同的条目编号会按资料标识分开。
- 修改馆藏：替换 `museum` 登记的表格，运行“更新 museum”。
- 以后换表格格式，改 `app/knowledge/readers.py`。校勘和能否给观众使用仍在 `records.py`、`collate.py`、`permissions.py`。换检索方式改 `app/knowledge/index.py`。

适合进代码仓库的是程序、规则、风格、原始表格、知识包正文和复刻音色参考。密钥与本机会话库不进仓库。

```bash
.venv/bin/python scripts/使用.py 检查
.venv/bin/python scripts/使用.py 生成
.venv/bin/python scripts/使用.py 加载
.venv/bin/python scripts/使用.py 更新 museum
.venv/bin/python scripts/使用.py 启动
```

`生成` 按登记重做知识，保留聊天。`更新` 只替换指定资料。读取失败时旧知识还在。网站已打开时，下一次提问会使用新索引。

## 几种记录不要混在一起

聊天记录存在 `data/maodun.db` 的会话表里，换页面、刷新、关闭浏览器和重启网站都不会清掉。当前浏览器只读取自己的对话。点“新对话”会另开一段，旧的留在“历史对话”里。删除当前对话或删除全部历史都会先确认，删除后刷新也不会再出现。下载只生成一份文本，不删除对话。

完整问答始终保存在 turns。发给模型的是近期原文、较早摘要和本轮找回的相关原文，不是“只保留最近一两轮就算整段记忆”。摘要失效时仍可回查原始 turns。

页面上正在显示的文字会随会话从数据库恢复。`__pycache__`、`.pytest_cache` 和临时合成音频可以删，不会连带删除聊天。`md.wma` 和 `data/voices/` 是复刻音色要用的录音，不能当临时文件删除。

## 常见问题先看哪里

- 网页打不开：确认启动命令仍在运行，地址是 `http://127.0.0.1:8000/`。
- 能打开但回答说资料还没准备好：先运行“加载”或“生成”。
- 回答说这一次没有答成：检查 `.env` 里的 DeepSeek 密钥是否已填，改完后重启。不要把密钥发给别人。
- 管理页导入了表格，观众回答却没有变化：管理页只核对旧演示表。观众资料用 `scripts/使用.py`。
- 麦克风没有文字：看 `.env` 的百度三项是否齐全，以及浏览器是否允许麦克风。
- 有文字没有声音：看阿里云三项和复刻音色开关。配置存在不等于已经试听成功。
- 改了人物规则或风格样本却没变化：这两个文件保存后应在下一问生效。若改的是 Python，需要重启。
- 某一句回答不对：先运行 `scripts/使用.py 诊断` 看这一轮的去向、取到的材料和每一稿，再决定改规则、改材料还是改程序。不要为某一句话单独加判断。
- 改了网页却没变化：刷新浏览器。若仍是旧样子，关闭页面重新打开。

日志写在启动网站的那个终端里。可重建的临时文件是 `__pycache__` 和 `.pytest_cache`，删除后会在下次运行时再生。生成的朗读声音由接口直接返回给浏览器，不在项目里长期保存。
