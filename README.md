# 中国现代文学馆 · 茅盾数字人

观众可以打开麦克风，向依据馆藏资料回答的“茅盾数字人”提问。这一版的主界面是对话：录音、识别、检索、显示回答。已配置语音合成时会播放声音。2D 人物还没有做，中央是可替换的状态动画。

详细的文件和接口对照见 [项目使用与接入说明.md](项目使用与接入说明.md)。

这是数字化模拟，不是茅盾本人。口头回答和史料原文分开保存、分开显示。

## 这台电脑上实际看到的环境

2026 年 10 月 10 日在这台开发电脑上检查过，不是按“有 NVIDIA 显卡”来设计的：

- 系统：macOS 15.7.4（Intel，x86_64）
- 处理器：Intel Core i9，八核
- 内存：16 GB
- 显卡：Intel UHD Graphics 630，以及 AMD Radeon Pro 5500M（4 GB）。没有 NVIDIA 显卡
- Python：3.13.7，路径是 `/usr/local/bin/python3`

所以计算放在云端。本机只保存资料、做中文检索和网页。

## 和 TRPL 的关系

TRPL 是微软为西奥多·罗斯福总统图书馆做的参考系统，仓库在 <https://github.com/microsoft/TRPL>，论文在 <https://arxiv.org/abs/2609.09368>。它分成四层：资料入库、馆员审核、带来源的检索问答、实时语音和人物。

值得沿用的是这几条做法，不是整套程序：

- 资料、审核状态、检索、回答、语音和画面分成独立模块。
- 回答必须能指回来源；没有模型时直接说明，不用假回答冒充。
- 检索可以换实现，问答逻辑不用重写。

不适合在这台电脑上整套运行，也没有把代码搬过来：

- 仓库大约有 949 个文件，要用 Docker（把很多服务装在一起跑的工具）和 Azure 的存储、数据库、队列模拟器。
- 名为通用检索的那一层，实际会连接 Azure AI Search 和 Azure OpenAI。改一个密钥不能让它离开 Azure。
- 语音和人物使用 LiveKit 等实时通信，还面向英文和罗斯福的人物设定。
- 16 GB 内存的 Intel Mac 不适合再跑这一整套容器。

本项目用本地文件夹保存表格原件，用 SQLite（一个单文件数据库）保存条目和导入记录，用本机中文检索代替 Azure 搜索。这些是真正换掉的功能，不是只改了配置名字。说明见 `THIRD_PARTY_NOTICES.md`。

## 模块怎么接

| 模块 | 现在的状态 | 以后怎么换 |
| --- | --- | --- |
| 资料导入 | 访客知识库由 `python -m app.cli import-corpus 目录` 导入四份原始资料 | 演示 Excel 仍可在管理页导入，但不参与访客回答 |
| 知识检索 | 访客检索在 `app/knowledge/index.py`，只索引允许使用的节点 | 禁用条目不会进入生成上下文 |
| 人物问答 | `app/knowledge/respond.py` 检索后调用 DeepSeek 官方 `deepseek-flash` | 人物规则只改 `data/persona/system_rules.txt` |
| 识别纠错 | 已实现规则。保留原始文字，不会把所有“矛盾”改成“茅盾” | 接在语音识别后面 |
| 语音识别 ASR | 百度实时识别 | 浏览器发送 16kHz 单声道 PCM，密钥只留在后端 |
| 语音合成 TTS | 阿里云百炼 CosyVoice，可使用已配置的复刻音色 | 朗读的是检查后的同一份正文 |
| 人物画面 | 未接入。页面保留状态动画 | 2D 或 UE 都接收同一种事件 |
| 会话 | 已实现历史、取消和新一轮。旧一轮的迟到结果会丢掉 | 播放也按这个标记避免重复播报 |

## 当前问答链路

页面文字或语音识别后的文字进入 `POST /api/ask`。`Runtime.ask` 只调用本地知识库：检索、规则检查，再请求 `https://api.deepseek.com/chat/completions`，模型名是 `deepseek-flash`。检查后的正文同时用于页面显示和语音合成。访客响应不带检索片段。

文字生成不再调用千帆，也不再按 `QA_PROVIDER` 切回旧路径。百度语音识别和阿里云语音合成仍使用各自的配置。

在项目根目录的 `.env` 填写：

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

不要把密钥写进 `web/` 或提交到 Git。修改配置后需要重启服务。

## 表格字段

不需要先把表重做一遍。程序认表头，两份已经看过的表都能导入：

- `茅盾_统一章节总表.xlsx`：1164 条，列是分开的，例如“原文引用（OCR文本）”“客观内容概括”“来源书名”“页码”“事实核验状态”。优先导入这一份。
- `茅盾_千帆知识库导入版_上册.xlsx`：列是打包的，例如“人物信息”“来源定位”“检索标签”。程序会拆开。它和总表有相同段落，不要两份一起导入，否则会变成两套条目，并给出“原文相同”的提醒。

认不出的列会原样留在条目里，不会丢。原文和概括永远分开放，概括不会盖住原文。小说人物台词会标成“不是茅盾本人的观点”。

同一文件名再次导入：内容没变就记为“未变化”，改过的行会更新，同一张表里重复的条目 ID 会记入错误，不会悄悄多插一条。

## 本机检索的限度

中文不能用英文那种“按空格分词”的默认办法。这里用结巴分词，并保留原句里的连续词语。书名只作为来源显示；如果每一行都写着同一个书名，它不会再让所有段落都变成命中。

一个问题里的几个关键词，必须出现在同一条资料里，才会拿来回答。所以“今天北京天气怎么样”不会因为某一页写了“北京”、另一页写了“天气”就被拼成答案。

它还做不到按意思去找同义词。例如资料里只写“老年”，问题只说一个资料里从没有出现过的说法，就可能找不到。

## 在这台 Mac 上安装和启动

在“终端”里执行：

```bash
cd /Users/zxn./Desktop/maodun
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

在 `.env` 填写 `DEEPSEEK_API_KEY`。模型名保持 `deepseek-flash`。然后导入知识库并启动：

```bash
.venv/bin/python -m app.cli import-corpus "/资料所在目录"
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

不要把密钥写进 `web/` 或提交到 Git；`.gitignore` 已排除 `.env`。修改配置后需要重启服务。

接入百度实时语音识别时，在同一个 `.env` 中填写：

```dotenv
ASR_PROVIDER=baidu_realtime
BAIDU_ASR_APP_ID=124580192
BAIDU_ASR_API_KEY=你的百度语音API Key
BAIDU_ASR_WS_URL=wss://vop.baidu.com/realtime_asr
```

接入阿里云百炼 CosyVoice 时，在 `.env` 填写：

```dotenv
TTS_PROVIDER=dashscope_cosyvoice
DASHSCOPE_API_KEY=你的百炼API Key
DASHSCOPE_WORKSPACE_ID=你的业务空间ID
DASHSCOPE_API_HOST=https://{workspace_id}.cn-beijing.maas.aliyuncs.com
DASHSCOPE_TTS_MODEL=cosyvoice-v3-flash
DASHSCOPE_TTS_VOICE=longanyang
DASHSCOPE_TTS_FORMAT=wav
DASHSCOPE_TTS_SAMPLE_RATE=24000
```

API Key、业务空间和 Host 必须属于同一地域；若不是北京地域，请把 Host 换成控制台提供的实际地域专属地址。程序调用 `/api/v1/services/audio/tts/SpeechSynthesizer`，不使用 `/compatible-mode/v1`。修改后重启服务。

浏览器不会拿到 API Key。点击“开始说话”后，浏览器把麦克风采样转换为 16kHz、单声道、16bit PCM，每 160ms 经本项目 WebSocket 转发给百度；临时文字只显示，点击“结束并发送”后才合并最终句子并调用一次问答。

先导入字段更全的那份表：

```bash
python -m app.cli import "/Users/zxn./Desktop/茅盾/茅盾_统一章节总表.xlsx"
```

启动网页：

```bash
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

浏览器打开 <http://127.0.0.1:8000> 。主页面是对话。资料导入和接口状态在 <http://127.0.0.1:8000/admin> 。

也可以不先用命令。打开网页后，进入“资料与设置”（地址是 `/admin`）上传表格，或粘贴上面的路径。演示资料按钮会导入四条标明“不是馆藏原文”的测试句，用来检查检索，不能当成茅盾的话。

运行自动检查：

```bash
pytest -q
```

## 建议这样确认

1. 再次导入同一份总表，应显示新增 0、未变化 1164，条目总数仍是 1164。
2. 提问“您为什么在晚年写《我走过的道路》？”。没有模型密钥时，口头回答一栏是空的，来源应能看到《我走过的道路》序 1、条目 PRE-P001。
3. 提问“行年五十而知四十之非，这句话怎么说的？”，来源应是序 1、条目 PRE-P002，并看到原文。
4. 提问“今天北京天气怎么样？”，应回答目前资料中没有找到相关记载，来源区是空的。
5. 配置百度 API Key 后，点击“开始说话”，允许麦克风权限，应能边说边看到临时识别文字；点击“结束并发送”后只出现一条用户问题并调用一次问答。

## 回答会分成三块

- **口头回答**：给观众看，以后也只把这一段送给语音合成。
- **依据**：条目编号、原文、来源、页码、发言人是谁。小说人物台词会单独标明。
- **控制信息**：情绪和动作，页面写明“不朗读”。没有人物程序时不会真的做动作。

证据不够时，系统直接说“目前资料中没有找到相关记载”，并且不调用模型。模型如果引用了本次证据以外的编号，这段话会被拦住，证据列表仍保留。

## 以后接语音和人物

文字输入和按键说话都可以使用。语音采用“开始说话 / 结束并发送”，不会一直开着麦克风，避免数字人把自己的声音又听成新问题。

每一轮有会话编号、轮次编号和“第几代”标记。取消或提出新问题后，晚到的识别、合成和画面事件都要丢掉。多句音频排队播放，不能同时响。

UE 或 2D 程序应接收页面里那种事件：`caption`（字幕）、`gesture`（动作）、`audio`（音频）。接入时要确认插件要的是 wav 还是 pcm，以及嘴型是否真的跟着音频走。本项目现在不运行大型声音克隆模型。

## 你接下来只要准备这些

程序、演示资料和《我走过的道路》上册这 1164 条已经能在本机用。先不用准备别的，也能浏览和检索。

要生成真正的人物口头回答，任选一种：

1. 千帆 API Key，并决定走路径 A（再填一个模型名）还是路径 B（再填应用 ID）。路径 B 的应用里要已经挂上知识库，并且接口会返回引用。
2. 或者另一个兼容聊天接口的地址、密钥和模型名。

语音识别代码已接百度实时接口，需要本机 API Key 才能使用。语音合成、声音样本和 2D 或 UE 人物仍未接入。

以后继续增加的 Excel，尽量保留“条目 ID、原文、概括、来源、页码”这几列，列名可以和现在两份表不完全一样。馆藏编号、书信、手稿和照片说明也可以加列，程序会把认不出的列留下来。
